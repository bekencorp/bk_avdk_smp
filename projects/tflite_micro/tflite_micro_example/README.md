# TensorFlow Lite Micro Example Project

* [中文](./README_CN.md)

## 1. Project Overview
This project is a combined TensorFlow Lite Micro (TFLM) and Ethos-U NPU example used to verify that the on-device inference pipeline works properly on the Beken platform.

The current example mainly implements the initialization and inference flow for the `person_detection` model:
- Initialize the TFLM runtime (`tflite::MicroInterpreter`)
- Load model data (generated by Vela)
- Configure and provide the scratch buffer for Ethos-U
- Configure the tensor arena for TFLM
- Acquire input images, run inference, and output the person / no person scores

This example also supports performance testing and inference time statistics.

## 2. Directory Structure
The project uses an AP/CP dual-core architecture, with the main logic running on the AP side. The directory structure is as follows:

## 3. Functional Description
### 3.1 Main Features
1. On-device inference pipeline verification: build and run the `person_detection` model with TFLM, and perform NPU-related initialization and interrupt handling through the Ethos-U driver.
2. Input and output processing: acquire input tensor data from the image provider, then read output tensors and calculate the probability percentages of `person_score` / `no_person_score`.
3. Output information: memory usage information is printed during initialization (scratch / tensor arena / model data), and the person / no person scores are printed after each inference.

### 3.2 Automatic Inference Time Measurement (DWT)
In `tflm_person_detection_demo.cpp`, `CONFIG_PERSON_DETECTION_INFER_TIME_AUTO` controls whether inference time statistics are enabled:
- When enabled, DWT cycles are used to record the cycle count before and after `Invoke()`
- The elapsed time is converted based on a fixed CPU frequency of `480MHz`
- Print format: it is printed in `us` when the inference time is less than `1ms`, and in `ms` when it is greater than or equal to `1ms`

Note: This feature is implemented through the compile-time switch `#ifdef CONFIG_PERSON_DETECTION_INFER_TIME_AUTO`, so this macro must be defined when building the project.

### 3.3 Memory / Performance Strategy (HSRAM / PSRAM / SRAM)
In `tflm_person_detection_demo.cpp`, the memory strategy is controlled by `PERSON_DETECTION_PERF_TEST`:
- When `PERSON_DETECTION_PERF_TEST=1` (performance mode): `EthosU0 Scratch` / `Tensor Arena` / `Model Data` are allocated from HSRAM first; if HSRAM is insufficient, they automatically fall back to regular SRAM allocation
- When `PERSON_DETECTION_PERF_TEST=0`: `EthosU0 Scratch` still uses HSRAM, while `Tensor Arena` / `Model Data` use PSRAM

In addition, this example requires 16-byte alignment for model data to satisfy Ethos-U command stream constraints. Performance mode is used to evaluate the peak NPU inference performance.

### 3.4 GPIO-Based Inference Time Observation (Logic Analyzer)
If `PERSON_DETECTION_DEBUG` is defined in `tflm_person_detection_demo.cpp`, specified GPIOs are toggled during different phases of inference:
- `GPIO_34`: toggled at the start / end of inference (useful for measuring the `Invoke()` duration with a logic analyzer)
- Other phases: `GPIO_32` / `GPIO_33` / `GPIO_35` are used to distinguish image acquisition, inference, result processing, and other stages

After connecting a logic analyzer, it is recommended to observe the high-level duration of `GPIO_34` to measure the inference time of a single run.

## 4. Build and Run
### 4.1 Build
Use the following command to build the project:
```
make bk7259 PROJECT=tflite_micro/tflite_micro_example
```

### 4.2 Run
After building and flashing the firmware to the development board, the serial log will show the inference task output:
1. An inference thread is created on the AP side
2. The inference task enters a loop and runs inference on two input samples in sequence (`paper` / `no person` and `rock` / `person`)
3. Output scores are printed after each inference

Example (log keywords may vary slightly by version):
```
===========>start person_detection demo
Start detecting person
person score:xx%, no person score yy%
Start detecting no person
person score:xx%, no person score yy%
```

If inference time statistics are enabled (`CONFIG_PERSON_DETECTION_INFER_TIME_AUTO`), an additional log similar to the following is printed after `Invoke()` completes:
```
Invoke time: xxx us
```
or
```
Invoke time: xxx ms
```

## 5. Test Plan
1. Functional verification: run the example directly and check whether person / no person scores are continuously printed, and confirm that there are no logs such as `Invoke failed`, `AllocateTensors failed`, or other initialization failures.
2. Performance verification (optional): enable `CONFIG_PERSON_DETECTION_INFER_TIME_AUTO`, observe the `Invoke time` log, and collect the typical inference time range (`us` or `ms`).
3. Memory strategy verification (optional): modify `PERSON_DETECTION_PERF_TEST` and observe the printed memory source of scratch / tensor arena / model data during initialization, as well as whether fallback is triggered.

## 6. Notes
1. The inference task in this example runs continuously and does not exit automatically after entering the loop
2. Ethos-U scratch and the tensor arena consume a relatively large amount of memory; make sure the corresponding memory regions are available
3. The 16-byte alignment requirement for model data must not be broken; alignment handling is already included in this example
4. DWT cycle conversion uses a fixed `480MHz`; if the actual platform frequency is different, the converted time may be inaccurate
